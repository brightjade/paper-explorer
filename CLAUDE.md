# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
uv sync                                        # Install dependencies
uv run ppr discover                            # Check tracked venues for new accepted-paper lists
uv run ppr crawl iclr_2025                     # Crawl one conference
uv run ppr crawl iclr_2025 neurips_2025        # Crawl multiple (one OpenReview login)
uv run ppr enrich iclr_2025 neurips_2025        # Enrich with Semantic Scholar metadata
uv run ppr enrich --all                        # Refresh citations; archive years (4+ old) follow a monthly cohort, batch-only
uv run ppr validate iclr_2025                  # Validate paper count against DBLP
./build.sh                                     # Build static JSON for web app
uv run ppr discover --json > discover.json     # Machine-readable sweep, autoregister's input
uv run ppr autoregister discover.json --report register.json   # Register live venues by rule (--commit commits each venue)
uv run ppr enrich --all --time-budget 4h --report enrich.json  # Enrich within a time budget
uv run ppr awards --all --report awards.json                  # Collect paper awards into data/<id>/awards.json
uv run ppr awards --all --all-years --report awards.json         # Also every older year (awards final; on request)
uv run ppr rolling --report rolling.json                      # Recrawl rolling venues (TMLR) without dropping a paper
uv run ppr release --base-tag data-YYYY-MM-DD --dry-run         # Plan a data release
uv run python -m scripts.sync_data                             # Mirror the newest data release into data/ (refuses over local edits)
uv run pytest tests/                           # Run all tests
uv run pytest tests/test_models.py::TestPaper::test_to_dict_full  # Single test
node tests/workflow/monthly-workflow.test.js   # The workflow's issue executor (github-script)
cd web && npm run lint && npm run build        # Web app checks (npm run dev serves /paper-explorer/)
```

## Convention

Conference ID = config filename without `.yaml` (for OpenReview) or key in `SCRAPERS` dict (for every other source: ACL-family / AAAI / USENIX / CVF / DBLP / researchr / Crossref / roboticsproceedings / IJCAI). Everything derives from it:

- Config: `configs/<id>.yaml` (OpenReview only)
- Scraper: `ppr.scrapers.SCRAPERS[<id>]` (every non-OpenReview source)
- Output: `data/<id>/papers.jsonl`
- Enriched: `data/<id>/papers_enriched.jsonl` (sorted by citation count, with abstracts)
- Awards: `data/<id>/awards.json` (from `ppr awards`; joined onto papers by `scripts/build_data.py`)

A new venue *prefix* (not a new year) is mirrored by hand in places autoregister never touches: `configs/venues.yaml`, `VENUE_NAMES` and `VENUE_CATEGORIES` in `scripts/build_data.py` (else it lands in "Others"), `VENUE_ORDER` in `web/src/categories.ts`, a row in README's conference table (autoregister only extends existing rows), the venue table in `.claude/skills/survey/SKILL.md`, and if it has awards `SOURCES_BY_PREFIX` in `ppr/awards/collect.py`. `ANNOUNCED_YEAR_BEFORE` / `CONFERENCE_MONTHS` in `scripts/impact.py` only if the venue announces outside its registry `announce_month`.

## Architecture

Multiple data sources, one output format:

- **OpenReview conferences** (ICLR, NeurIPS, ICML, COLM, CoRL): conference ID -> YAML config -> `OpenReviewAPIClient` -> API (`get_all_notes` with invitation + venueid) -> filter by `venue` field -> `Paper` with `selection` tag. TMLR (`tmlr_<year>`, 2022+) has one `TMLR` venueid for all years, so its configs set `year_from_pdate: true` and keep only the notes whose `pdate` year is the config year; each such paper stores that date as `venue_date`. TMLR is `rolling` in the registry: it has no accepted-list date, so `ppr rolling` recrawls the current year monthly (last year's too, January through March) and holds the venue rather than drop a paper already on disk.
- **ACL-family conferences** (EMNLP, ACL, NAACL, EACL, COLING): conference ID -> `ppr.scrapers.acl.SCRAPERS` -> scrape the conference website's accepted-paper pages (`<li>` or `<p>` title/author layouts), or ACL Anthology volume pages for EACL and COLING 2024 -> `Paper` with `selection` tag
- **AAAI**: conference ID -> `ppr.scrapers.aaai.SCRAPERS` -> scrape OJS issue pages from `ojs.aaai.org` -> `Paper` with `selection` tag
- **USENIX Security**: conference ID -> `ppr.scrapers.usenix.SCRAPERS` -> scrape `article.node-paper` from `technical-sessions` page -> `Paper` with `selection` tag. Requires browser User-Agent header.
- **CV conferences** (CVPR, ICCV, ECCV, WACV): conference ID -> `ppr.scrapers.cvf.SCRAPERS` -> CVF Open Access (or the conference's AcceptedPapers page before proceedings appear) / ECVA for ECCV -> `Paper` with `selection` tag
- **Robotics conferences** (ICRA, IROS): new years -> `ppr.scrapers.crossref.SCRAPERS` -> Crossref works by exact proceedings title (`container-title`), front matter (author-less items) dropped, DOI links. 2023-2025 stay on DBLP (`ppr.scrapers.dblp`). **RSS** -> `ppr.scrapers.roboticsproceedings.SCRAPERS` -> `roboticsproceedings.org/rss{NN}/index.html` (NN = year - 2004), DOIs derived as `10.15607/RSS.<year>.<ROMAN>.<NNN>`.
- **SE conferences** (ICSE, FSE, ASE, ISSTA): conference ID -> `ppr.scrapers.researchr.SCRAPERS` -> the venue's research track on `conf.researchr.org` (research track only). Entries with a `dblp` key take DBLP's record (title, authors, DOI) for every paper matched by `title_key`, and fail below an 80% match or when DBLP is unreachable.
- **IJCAI**: 2023-2025 -> `ppr.scrapers.dblp.SCRAPERS` -> DBLP SPARQL. 2026 -> `ppr.scrapers.ijcai.SCRAPERS` -> conference website.
- **Backfill 2013–2022**: ICLR 2017–22, NeurIPS 2021–22 and CoRL 2021–22 are OpenReview v1 configs (ICLR 2018–20 read their labels from decision notes via `decisions`; ICLR 2017 sets `submission_invitation`). Every other venue-year comes from `configs/backfill/dblp.yaml`: the toc pages (proceedings volumes) of the main conference with a selection each (`main` / `findings` / `industry`), generated once from DBLP and reviewed by hand, merged into `DBLP_CONFERENCES`.

All produce JSONL. Enrichment (citations + abstracts via Semantic Scholar) works the same for all sources. OpenReview abstracts are preserved; Semantic Scholar abstracts fill in papers that lack them.

### Key modules

Pipeline code lives in the `ppr/` package; `scripts/` holds the web-data build and the data mirror:

- `ppr/cli.py` -- Entry point (`ppr`) with subcommands: `crawl`, `enrich`, `validate`, `discover`, `autoregister`, `report`, `release`, `awards`, `rolling`. `crawl` accepts multiple conference IDs, logs into OpenReview once per API version, and scrapes every other source without auth.
- `ppr/api_client.py` -- `create_openreview_client()` logs in once (API v2; `create_openreview_v1_client()` for the configs that set `api_version: 1` -- iclr_2017–2023, neurips_2021–2022, corl_2021–2023). v1 can read labels from decision notes (`decisions`), fetches `extra_venue_ids` too, and collapses notes that repeat a paper (same title and authors; NeurIPS 2021 lists 297 twice). `OpenReviewAPIClient` takes the client + config. Fetches accepted papers in one API call (plus one per `extra_venue_ids` entry) and filters by `venue` string client-side; configs with `decisions` read labels from decision notes instead, through a second call or direct replies.
- `ppr/scrapers/` -- Web scrapers for conferences not on OpenReview. Each module exports a `SCRAPERS` dict mapping conference IDs to scraper functions. `ppr/scrapers/__init__.py` aggregates all scrapers.
  - `acl.py` -- ACL-family (EMNLP, ACL, NAACL, EACL, COLING). Handles separate-page, single-page and paragraph layouts on conference sites, and ACL Anthology volume pages. Skips list entries without authors (filters footer noise).
  - `aaai.py` -- AAAI proceedings from `ojs.aaai.org`. Scrapes multiple OJS issue pages per year (technical tracks + special tracks).
  - `usenix.py` -- USENIX Security. Scrapes `technical-sessions` page (`parse_sessions`). Authors are the people-text first `<p>`'s text outside `<em>` (affiliations are inside it); later `<p>`s are notes, which the awards collector reads. Needs browser UA to avoid 403.
  - `dblp.py` -- ICRA/IROS/IJCAI 2023-2025 from DBLP toc pages via `ppr/dblp_client.py`. Maps records to papers; skips records without a document page. Also loads the 2013–2022 backfill from configs/backfill/dblp.yaml; a backfill toc that yields no paper fails the conference.
  - `researchr.py` -- SE research tracks on conf.researchr.org. `parse_track_page` (shared by the probe) reads the page title's track name and the `#event-overview` rows of that track, returns each row's badge strings (read by the awards collector) and keeps them and "[Remote]" tags out of titles. Paced at robots.txt's `Crawl-delay: 2`; plain paths only.
  - `crossref.py` -- ICRA/IROS by exact Crossref `container-title`. Cursor paging that raises if it ends short, markup-stripped titles, no `mailto`.
  - `roboticsproceedings.py` -- RSS proceedings volumes; one index request per volume.
  - `cvf.py` -- CV conferences (CVPR, ICCV, WACV) from CVF Open Access, or from the conference's AcceptedPapers page before proceedings appear (ICCV 2025, WACV 2026, no paper links); ECCV from ECVA. Parses paper lists with author metadata.
  - `ijcai.py` -- IJCAI 2026 from the conference website (`2026.ijcai.org/accepted-papers`), which lists all papers as `<li class="ij-paper">` with title, authors, abstract, and topic keywords. IJCAI 2023-2025 stay on DBLP; 2026 isn't indexed there yet. Needs a browser UA.
- `ppr/s2_client.py` -- Single point of contact with the Semantic Scholar Graph API. Owns pacing and 429/403 exponential backoff, shared by all three endpoints: `match_title` (one paper by title, heavily throttled to ~0.3 req/s), `get_batch` (up to 500 IDs per request -- `CorpusId:`, `DOI:`), and `bulk_search` (venue+year, 1000 papers per page). Returns raw API dicts. `ENRICHMENT_FIELDS` requests `authors` alongside the citation metadata, which `match_verdict` needs to break ties titles alone cannot settle.
- `ppr/matching.py` -- Decides whether a Semantic Scholar record is the paper we crawled. `title_key` canonicalises titles across sources (NFKC, LaTeX and unicode Greek onto one token, then alphanumerics only); `match_verdict` returns `matched` / `matched_fuzzy` / `reject`, using author-surname overlap to break ties that titles alone cannot. `/search/match` answers an unindexed paper with its nearest fuzzy neighbour rather than with nothing, so an unchecked result is how a paper ends up wearing a stranger's citations.
- `ppr/enrich.py` -- Per-conference enrichment. Picks the cheapest workable path: **refresh** (batch by `CorpusId` from the existing enriched file), **id-cold** (batch by `DOI` from the crawler's `link`, for venues whose crawler links are DOIs: DBLP, Crossref, roboticsproceedings, and researchr entries backfilled from DBLP; a DOI Semantic Scholar has no record under falls through to title-cold, since DBLP records DOIs it never linked; archive batch-only runs count it untried instead), or **title-cold** (bulk prefetch by venue+year, then per-title matching for the misses; `bulk_years` prefetches year-1 and year for `tmlr`, because S2 dates a TMLR paper by its arXiv version). Every run re-attempts papers no earlier run could match -- Semantic Scholar indexes a venue months after we crawl it, so "not found" expires. Each refresh also re-verifies the binding against the returned title and authors (`ppr/matching.py`) and unbinds a record that turns out to describe a different paper, which returns it to the same retry queue. Two guards refuse to overwrite good data with bad: `check_guards` bounds how many *papers* a run may lose -- refusing when `papers.jsonl` is empty or under 50% of the enriched count; `check_enrichment_coverage` bounds how much *enrichment* a run may lose -- refusing when fewer than 50% of previously matched papers would keep a `CorpusId`, which the paper count alone cannot see, and which also caps how much a single run's verification is allowed to unbind. Writes atomically via temp file + `os.replace`, sorted by citation count. `--time-budget` stops only the per-title matching loop; unmatched papers past the deadline are written unchanged and counted `deferred`, and conferences run newest year first (`--time-budget 0s` is an already-spent deadline, not unlimited). `--report` is written even when a conference failed.
- `ppr/archive.py` -- Archive years: a conference is archive once `year <= today.year - 4`. `ppr enrich --all` refreshes archive conferences batch-only (CorpusId and DOI, never title matching) one `crc32(conf_id) % 3` cohort a month, before live conferences so the cost falls inside the time budget; the rest report `not-due`. Named conferences, `--require` ones and `--full` runs get a full enrich. `discover.missing_years` never probes archive years.
- `ppr/dblp_client.py` -- Single point of contact with DBLP, through `sparql.dblp.org` (dblp.org itself is behind an Anubis wall that answers every client 202, and its robots.txt disallows `/search/publ`). `toc_count(keys, number)` counts any number of toc pages in one query; `toc_papers(key, number)` returns cleaned records with ordered authors and a DOI-first link. Paced at the endpoint's `Crawl-delay: 10`, retries `{429, 500, 502, 503, 504}` honoring `Retry-After`, names a 202 "bot challenge", and raises `DblpUnavailable` on anything short of a complete answer.
- `ppr/net.py` -- `PROJECT_USER_AGENT`, the one honest User-Agent every new client sends, and `parse_retry_after`, the `Retry-After` parser the DBLP and Crossref clients share.
- `ppr/validate.py` -- Cross-references scraped paper counts against DBLP proceedings data. Maps conference IDs to DBLP toc keys, counts them in one SPARQL query, compares with configurable tolerance (default 10%). Skips DBLP-sourced conferences (circular validation). A throttled sweep is `ERROR`, never `FAIL`.
- `ppr/venues.py` -- Loads `configs/venues.yaml`, the registry of 25 tracked venue prefixes (source, cadence, probe template, announce month, and `rolling` for an OpenReview venue with no accepted-list date, TMLR). Validation is strict: an unknown source or cadence raises rather than silently skipping the venue.
- `ppr/discover.py` -- Finds conference-years whose list is published but unregistered. `known_conference_ids()` comes from `configs/*.yaml` + `SCRAPERS`, never from `data/`, so it runs in CI without the dataset. Every probe reports a **parsed paper count**, never an HTTP status: CVPR 2026 returns 200 with an empty stub, WACV 2027 returns 404 with a 29KB body. Statuses are `live` / `empty` / `not-yet` / `unreachable` / `needs-manual`. DBLP probes go through `ppr/dblp_client.py`; researchr probes try the venue's ordered `track_slugs` and record the one that matched; Crossref probes are exact counts; OpenReview needs credentials (anonymous queries are refused); a rolling venue's OpenReview probe counts only notes whose `pdate` year is the probed year.
- `ppr/register.py` -- Writes registration entries for mechanical sources. `selections_from_notes()` (wrapped by `openreview_selections()`, which fetches the notes) derives a config's `selections` from the venue's actual `venue` values rather than a pattern; autoregister holds a venue whose derived names fall outside `TRACK_VOCABULARY`.
- `ppr/rolling.py` -- `ppr rolling`: `due_ids` picks each rolling venue's current-year id (and last year's through March) that already has config and data; `recrawl_rolling` recrawls it and, if any paper on disk (matched by forum_id, else `title_key`) is missing from the new crawl, holds the venue and keeps the file. Failures are per venue; always exits 0; logs into OpenReview lazily. `--report` feeds the issue decision (`report.py` opens it for held/failed rolling rows).
- `ppr/autoregister.py` -- Turns `discover --json` `live` rows from mechanical sources (OpenReview, DBLP, CVF, USENIX, researchr, Crossref, roboticsproceedings) into registrations without a human: writes the registry entry from the probe's `registration` payload, crawls, holds the venue if the count is more than 10% off the probe, is under half of the nearest earlier edition's (year-1, else year-2; not for a `rolling` venue, whose registration also renders `year_from_pdate: true`), or `validate` says `FAIL` (in practice only for venues that already have a DBLP validation key in `DBLP_VALIDATION_KEYS`; a new venue gets `NO_DATA`, so the cross-check does not fire), adds the year to the venue's README row, and commits each venue with `git commit -- <paths>` (unstaging them if the commit fails). A held venue has every edit reverted (including a pre-existing `data/<id>`) and comes back next month.
- `ppr/report.py` -- `pipeline_state.json` deferral streaks, and the tracking-issue decision (`notify` / `blind` / `close`). Issues exist only for what a human must act on. The workflow's github-script only executes this decision; the executor is tested by `node tests/workflow/monthly-workflow.test.js`.
- `ppr/release.py` -- Publishes `data/` as a `data-YYYY-MM-DD` GitHub Release: refuses if the newest data release is not the one the run started from, creates before pruning, keeps 3. The newest data release is the dataset's source of truth.
- `.github/workflows/monthly.yml` -- 07:23 UTC on the 3rd: discover → autoregister → recrawl → rolling recrawl (`ppr rolling`) → tests → awards → enrich (210m budget) → release → push → dispatch deploy, with a separate `notify` job for the issue. Installs with `uv sync --locked`, fails closed if `data.zip` extracts no conference data, and refuses non-dry-run runs that do not start from `main` (dry runs work from any branch). A `workflow_dispatch` `recrawl` input re-crawls the listed conference IDs before enrich, and `ppr enrich --require` fails the run before release unless each of them ends enriched. An `awards_all_years` input adds `--all-years` to the awards step.
- `ppr/awards/` -- Paper awards, kept apart from crawl and enrich because they are announced months after the accepted list. `labels.py` maps each label a venue prints onto one of five kinds (`award`, `honorable`, `candidate`, `artifact`, `test_of_time`); an unknown label raises `UnknownAwardLabel` (researchr badges excepted: most are artifact or topic badges). One module per source -- `virtual.py` (awards_detail, CVPR AwardCandidates), `iclr_blog.py` (WordPress REST: outstanding-paper posts with a forum-id join, and test-of-time posts), `cvf_registry.py` (thecvf.com, every CVPR/ICCV/ECCV prize), `researchr_badges.py`, `sigsoft.py` (SE backfill), `icse_mip.py`, `ase_mip.py`, `issta_impact.py` (each venue's test-of-time page, all years on one page), `usenix_notes.py`, `usenix_tot.py` (Test of Time page), `tmlr_certifications.py` (live OpenReview read; Outstanding → `award`, Featured → `honorable`, other known certifications ignored, an unknown one raises; TMLR labels live in `PREFIX_ONLY`, no default rules), `manual.py` (`configs/awards_manual/<id>.yaml`, reviewed one-off lists) -- fetched through `fetch.py` at each host's robots.txt Crawl-delay. `collect.py` runs each venue's ordered `SOURCES_BY_PREFIX` list, merges (earlier source wins a duplicate), and ends each conference `collected` / `not-yet` / `held` (unknown label, or it would lose entries) / `failed` (source raised); held and failed keep the file on disk and exit 0. `ppr awards --all` covers this year and last year (`RECENT_YEARS`), plus every year from `FIRST_YEAR_BY_PREFIX` (TMLR: 2022); `--all-years` (the workflow's `awards_all_years` input) adds every older year, whose awards are final; named ids run as given. `join.py` binds entries to papers by forum id, else `title_key`; a test-of-time prize is conference-level where it was given, and `attach_test_of_time` (called by `build_data`) also puts it on the honored paper when an earlier edition of the same venue holds it.
- `ppr/models.py` -- `Paper` dataclass with `selection` field. `to_dict()` excludes `None`, empty-string and empty-collection fields. `write_papers()` is the one way `papers.jsonl` gets written, by both save paths, and refuses to replace a non-empty file with zero papers (`EmptyOverwriteError`) -- a broken source returns `[]`, not an exception.
- `ppr/config.py` -- `CrawlConfig` from YAML. `conference_id` derived from filename, output path derived from that.
- `ppr/readme_table.py` -- Adds a registered year, and any new track label, to its venue's row in README's one conference table (`| Field | Venue | ID | Years | Tracks |`), in place. `parse_years` / `format_years` read and write the Years cell (runs like `2013, 2015–2026`, or `2013–2025 (odd years)` for a biennial venue); a test fails on any hand-written cell they would not write back unchanged. The stats row at the top of README (papers, conference-years, citations) is hand-written and rounded.
- `scripts/build_data.py` -- Builds the web app's static JSON in `web/public/data/` from `data/`: the manifest (with each conference's `category`), the author index, trends via `scripts/ngrams.py`, one file per conference (with `data/<id>/awards.json` joined onto its papers, and test-of-time entries in the manifest, and test-of-time prizes also on the honored paper via `ppr.awards.join.attach_test_of_time` before impact/`top.json`), and `top.json` via `scripts/impact.py`. `./build.sh` wraps it. The app itself is in `web/` (see `web/README.md`). No .jsonl copies are shipped: the Download button builds the JSONL in the browser from the per-conference JSON and drops build-time fields such as `relative_citations`.
- `scripts/impact.py` -- The age-adjusted metric and the Top 100 lists. `relative_citations` is a paper's citations divided by the mean of the papers in the dataset first made public in the same quarter. The first-public date is the earliest of the arXiv id month (also read from arXiv's DataCite DOI and the DBLP CoRR key), the S2 date and the conference date. A paper with a `venue_date` (TMLR) uses it as the conference date; otherwise the conference date is day 15 of the registry's `announce_month`, in the year before for AAAI and WACV (`ANNOUNCED_YEAR_BEFORE`), and pinned per conference for COLING, which moves around the calendar (`CONFERENCE_MONTHS`). Quarters under 300 cited papers merge into the one before. It is relative to the whole corpus, so it lives only in the build output, never in `data/` or the download JSONL. `top.json` holds the top 100 for every (all / year) × (all / category) × (relative / citations), as indices into one deduplicated paper pool.
- `scripts/sync_data.py` -- Mirrors the newest data release into `data/`. A no-op while `data/` already holds it; refuses to replace a `data/` it did not install or that changed since (`--force` overrides), tracking what it installed in `.data-release.json`.

### OpenReview API notes

- All accepted papers share one `venueid` (e.g., `ICLR.cc/2025/Conference`), not per-track IDs
- Track type is in `venue` content field (e.g., `"ICLR 2025 Oral"`)
- Casing varies: ICLR 2025 title case, NeurIPS 2025 lowercase, ICML 2025 uses `spotlightposter`
- Auth mandatory (free account). Login rate-limited to 3/min -- `crawl` reuses one login per API version for all OpenReview conferences.
